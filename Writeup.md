## 1. What was the most challenging part? Did you find HTML and CSS easy or difficult?

The most challenging part is the css, this part takes me the longest, because it take me a while to figure out what design or formating I want. Also the puzzle part took me a while to figure out how to implement it into my website. I think the HTML part is pretty easy.

## 2. How did you build the puzzle grid, and what other options did you consider?

I built the grid with CSS Grid: a 5×5 board where each open square is a text input that holds one letter, and the four corner squares are blocked out. Each input has a label for screen readers, and the solution is hidden which you can click or tap to open. 
I also thought about using an HTML table or a checkbox to show the answers, but CSS Grid is simpler and easier to make work on phones.

## 3. What did you take into account when designing the site? Anything you're proud of?

I wanted the site to be simple, easy to read and work well on phones. I picked one accent color (violet) with neutral grays and saved my colors and spacing as CSS variables, so every page looks the same. I also make sure the site works with a keyboard and everything you can tap is at least 44px. 
I am proud of the feature I added to reveal the solution in the puzzle. It will hide the solution normally, but after u click or tap it, it will open to show you the solution, and it worked fine without using javascript

## 4. Given more time or resources, what would you add?

If i can have more time or resources, I may add a couple more mini games to the website. And I will change the puzzle Navbar into a game selection page, which u can choose one of the games. And if possible, I also want to make another Navbar for some game recemandation.
